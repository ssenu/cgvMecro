# CGV 감시 + 좌석 확보 통합 설계 (노트북 단독 실행)

- 날짜: 2026-08-26
- 상태: 사용자 승인됨
- 선행 문서: `2026-08-19-linux-web-redesign-design.md` (현재 감시 앱 설계)

## 목표

지금의 감시·알림 앱(cgvwatch)과, 별도로 만들어 두었던 좌석 확보 스크립트(`hunterH.js`)를
하나의 노트북 프로그램으로 통합한다. 예매가 열리거나 취소표가 나오면 **로그인된 크롬을
자동으로 조종해 좌석 선택까지 마치고 결제 직전에 멈춘 뒤 사람을 부른다.**

로그인과 결제는 사람이 한다. 프로그램은 그 사이의 "새로고침하고 자리 클릭하기"만 대신한다.

## CGV API 관찰 기록 (2026-08-26 확인)

이 절은 코드에 없는 정보다. 깨졌을 때 가장 먼저 확인할 것.

**공통**
- Base URL: `https://cgv.co.kr/api/v1/booking/`
- 모든 요청에 `coCd=A420` 필요
- **`Referer: https://cgv.co.kr/` 헤더가 없으면 일부 엔드포인트가 403을 반환한다.**
  (`searchSiteScnscYmdListByMov`에서 실제로 겪음. 2026-08-19 수정)
- 응답은 `statusCode`가 0이면 성공, `data`에 본문. 단 `searchIfSeatData`는 형식이 다르다(아래).
- 과도한 폴링 시 429가 반환된다.

**엔드포인트**

| 엔드포인트 | 파라미터 | 반환 |
|---|---|---|
| `searchAtktTopPostrList` | `movNm=&div=&attrCd=` | 상영예정작 목록 (`movNo`, `movNm`) |
| `searchRegnList` | 없음 | 지역별 극장 (`regnGrpNm`, `siteList[].siteNo/siteNm`) |
| `searchSiteScnscYmdListByMov` | `siteNo`, `movNo` | 예매 오픈된 날짜 목록 (`scnYmd`) |
| `searchSchByMov` | `siteNo`, `movNo`, `scnYmd`, `rtctlScopCd=08` | 회차 목록 |
| `searchIfSeatData` | `siteNo`, `scnYmd`, `scnsNo`, `scnSseq`, `seatAreaNo=001`, `cusgdCd=01` | 좌석 지도 전체 |

**회차 (`searchSchByMov`) 주요 필드**
- `scnsNo` (상영관 번호, 예 `"003"`), `scnSseq` (회차 순번, 예 `"2"`) — 좌석 조회에 필요
- `scnsNm` (관 이름, 예 `"3관 (Laser)"`, `"IMAX관"`) — 관 필터 판정에 사용
- `scnsrtTm` (시작 시각 `"1230"`), `frSeatCnt` (잔여석), `stcnt` (총 좌석)

**좌석 지도 (`searchIfSeatData`) — 로그인 불필요**
- 최상위에 `resultCode`, `items[]`. `items[0].seats[]`에 좌석 전체가 들어있다.
- 좌석 필드:
  - `seatRowNm` (행, `"A"`~), `seatNo` (번호, `"12"`), `seatLocNo` (고유 ID)
  - `seatStusCd`: `"00"` 빈자리 / `"01"` 판매완료 / `"04"` 선점중(결제 진행)
  - `seatSaleYn`: `"Y"`면 판매 가능
  - `xcoordStartVal`, `ycoordStartVal`: 좌표 문자열(`"0023"` 등)
- **좌표 규칙**: 같은 행은 `y`가 같고, 옆자리는 `x`가 2 차이. 통로가 있으면 간격이 벌어진다.
  → 2인 연석 판정을 DOM 없이 좌표만으로 할 수 있다.
- 검증 예 (2026-08-26, 강남 3관): 172석 중 빈자리 158, 행 A~M.

## 예매 페이지 / DOM 관찰 기록 (2026-08-23 hunterH.js 기준, 재확인 필요)

- 예매 페이지: `https://cgv.co.kr/cnm/movieBook/movie?movNo=&scnYmd=&siteNo=&siteNm=`
  (영화·날짜·극장이 미리 선택된 상태로 열린다)
- 좌석 페이지: `/cnm/selectVisitorCnt` — 인원 선택과 좌석 선택이 한 화면에 있다
- 셀렉터 (**자동 생성 클래스명이 섞여 있어 CGV 배포 시 깨질 수 있음**):
  - 인원 선택 박스: `div.numberChoice_NumberWrap__JKTv1`
  - 인원 버튼: `button[aria-label="1 선택"]` / `"2 선택"` (`aria-pressed="true"`면 선택됨)
  - 좌석 버튼: `button[data-seatlocno]` — 텍스트가 좌석명(`"H12"`), `disabled`면 선택 불가
  - 모달: `.cgv-modal.active` — 안의 `확인|닫기` 버튼으로 닫는다
  - 휠체어석 경고: 모달 텍스트에 `휠체어|장애인` 포함 → 그 좌석은 블랙리스트
  - 좌석 확보 완료 신호: 본문에 `선택하신 좌석` 문구
  - 다음 단계 버튼: 텍스트가 `선택완료`인 `button` (공백 제거 후 비교)
- 결제 페이지 도달 판정: `location.pathname`이 `/cnm/selectVisitorCnt`가 아니게 되는 순간

## 아키텍처

노트북에서 `python run.py` 하나로 뜨는 단일 프로세스. 세 층으로 나뉜다.

**감시(watcher)** — 기존 코드 유지. CGV API를 주기적으로 조회해 날짜 오픈·관 조건을 판정하고
디스코드로 알린다. Playwright에 의존하지 않는다.

**헌터(hunter)** — 신규. Playwright로 로그인된 크롬을 조종한다. 좌석 페이지까지 진입하고,
좌석 지도 API를 폴링하며 빈자리가 생기면 클릭해 확보한다.

**웹 UI** — 기존 확장. 감시 등록 시 헌팅 옵션을 켜고, 진행 상황과 확보 결과를 본다.

감시와 헌터는 **헌트 큐**로만 연결된다. 감시는 "이 항목이 조건을 만족했다"를 큐에 넣을 뿐이고,
헌터가 어떻게 동작하는지 모른다. 헌터도 감시 로직을 모른다.

## 두 시나리오는 하나의 파이프라인

"새 오픈 잡기"와 "취소표 잡기"는 같은 일이다 — *특정 회차의 좌석을 지켜보다 자리가 나면 잡는다*.
차이는 날짜가 이미 열렸는지뿐이다. 감시 항목 하나에 헌팅 옵션을 켜두면:

- 날짜가 아직 안 열렸으면 → 오픈을 기다렸다가 회차를 골라 진입 (새 오픈 시나리오)
- 날짜가 이미 열렸으면 → 바로 회차를 골라 진입해 빈자리를 노림 (취소표 시나리오)

별도 모드를 만들지 않는다.

## 헌팅 흐름

1. 감시 스레드가 조건 충족(날짜 열림 + 관 필터 일치)을 감지하고 헌트 큐에 넣는다.
2. 헌트 매니저는 **활성 헌팅이 없을 때만** 큐에서 하나를 꺼낸다.
3. 회차 선택: `searchSchByMov`로 회차 목록을 받아 관 필터에 맞는 것 중
   선호 시각에 가장 가까운 회차를 고른다(선호 시각 미설정이면 가장 이른 회차).
4. 브라우저를 예매 페이지로 보내 그 회차를 클릭하고 좌석 페이지에 진입한다.
5. 인원을 설정한다.
6. 좌석 지도 API를 1초 간격으로 조회한다. 빈자리 후보가 있으면 페이지를 새로고침하고
   좌석 버튼을 클릭한 뒤 `선택완료`를 누른다.
7. 결제 페이지로 넘어가면 **모든 자동 동작을 중단**하고 알린다.
8. 클릭 경합에서 밀리면 다음 후보 좌석으로 재시도한다. 후보가 없으면 폴링으로 돌아간다.

헌팅은 **최대 1시간** 머물다 실패로 끝난다. 무한정 폴링하지 않는 이유는 차단 위험과
방치된 자동화를 피하기 위해서다. 더 오래 노리려면 웹 UI의 "지금 헌팅" 버튼으로 다시 시작한다.
이 버튼은 이미 열린 회차의 취소표를 노릴 때도 쓴다(감시는 '새로 열리는 순간'에만 자동 요청하므로).

## 좌석 선택 알고리즘

좌석 지도 API 결과만으로 판정한다(DOM 측정 없음). 순수 함수로 분리해 단위 테스트한다.

- **빈자리**: `seatStusCd == "00"` 이고 `seatSaleYn == "Y"`
- **기준점(중앙)**: 좌석이 존재하는 행들의 중앙 행과, 번호의 중앙값
- **오프셋**: 설정값만큼 뒤쪽 행으로 이동 (기본 +1행, 스크린에서 먼 쪽)
- **앞줄 제외**: 전체 행의 앞 20%를 비율로 제외 (관 크기가 달라도 동작)
- **점수**: `|행거리| * 2 + |번호거리|` — 행 차이를 번호 차이보다 무겁게 본다 (기존 로직 유지)
- **2인**: 같은 `y`, `x` 차이가 2인 쌍만 후보. 쌍의 점수는 두 좌석 점수의 평균
- **블랙리스트**: 휠체어석 모달이 뜬 좌석은 세션 동안 제외

## 브라우저 연결과 로그인

Playwright의 전용 프로필(`~/.cgv-watcher/chrome-profile`)로 크롬을 실행한다.
웹 UI의 "브라우저 열기" 버튼을 누르면 창이 뜨고, 사용자가 CGV에 직접 로그인한다.
세션은 프로필에 남아 다음 실행에도 유지된다.

**계정 정보는 저장하지도 다루지도 않는다.** 자동 로그인 기능은 만들지 않는다.

로그인 여부는 예매 페이지에서 로그인 UI 존재로 판정한다. 세션이 끊겼으면 헌팅을 시작하지 않고
UI에 "로그인 필요"를 표시하며 디스코드로 알린다.

## 유지보수를 위한 구조

CGV가 화면을 바꾸면 깨진다는 것을 전제로 만든다.

- **셀렉터 중앙화**: 모든 DOM 셀렉터와 URL 경로를 `cgvwatch/hunt/selectors.py` 한 곳에 모으고
  각 항목에 **관찰 날짜를 주석으로** 남긴다.
- **구조 변경 감지**: 좌석 버튼을 못 찾거나 `선택완료` 버튼이 없으면 조용히 실패하지 않고
  `⚠️ 화면 구조 변경 의심` 디스코드 알림을 보내고 페이지 스냅샷을 `data/snapshots/`에 저장한다.
- **원본 보존**: `hunterH.js`를 `docs/reference/hunterH.js`로 복사해 레포에 남긴다.
  (원본 폴더가 사라져도 참조할 수 있도록)

## 하지 않는 것 (안전선)

코드에 상수로 박고 문서에 이유와 함께 남긴다.

- 자동 로그인을 만들지 않는다 — 계정 정보를 프로그램이 다루지 않기 위해
- 결제를 자동화하지 않는다 — 결제 페이지 도달 즉시 정지
- 폴링 간격 하한 1초, 429 시 지수 백오프 — 차단 위험과 서버 부담을 줄이기 위해
- 동시 헌팅 1개 — 요청량을 늘리지 않기 위해
- 좌석 확보 후 추가 시도 중단 — 중복 선점을 만들지 않기 위해

## 에러 처리

- **CGV API 오류**: 해당 감시를 오류 상태로 표시하고 다음 주기 재시도 (기존 로직 유지)
- **429**: 폴링 간격을 늘리며 재시도, 반복되면 헌팅을 중단하고 알림
- **브라우저 없음/로그인 끊김**: 헌팅을 시작하지 않고 알림
- **셀렉터 실패**: 구조 변경 의심 알림 + 스냅샷 저장 후 해당 헌팅 중단
- **좌석 확보 실패**: 다음 후보로 재시도, 후보 소진 시 폴링 복귀

## 테스트

- **순수 로직은 단위 테스트**: 좌석 선택(좌석 지도 픽스처), 회차 선택, 관 필터, 중앙 계산
- **API 클라이언트**: 응답 픽스처로 파싱 테스트 (기존 방식 유지)
- **브라우저 제어**: 실제 CGV에 의존하므로 자동 테스트하지 않는다. 대신 셀렉터 상수를
  한 파일에 모아 변경 지점을 좁히고, 수동 스모크 절차를 `CLAUDE.md`에 기록한다.
- 기존 테스트 55개는 계속 통과해야 한다.
