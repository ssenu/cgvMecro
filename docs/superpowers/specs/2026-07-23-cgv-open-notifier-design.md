# CGV 예매 오픈 알리미 — 설계 문서

작성일: 2026-07-23

## 1. 목적

CGV에서 사용자가 지정한 **(상영관, 날짜, 영화 제목)** 조건에 대해, 아직 예매가 열리지 않은 영화의 **상영시간표가 처음 뜨는 순간(예매 오픈)** 을 감지하여 **이메일로 알림**을 보낸다.

- 이것은 **알림 도구**다. 좌석을 자동으로 선점/결제하는 **자동 예매 봇이 아니다.**
- 로그인·결제 없이 공개된 상영시간표 페이지만 예의 있게(polite) 주기 조회한다.

## 2. 사용 결정 사항 (브레인스토밍 확정)

| 항목 | 결정 |
| --- | --- |
| 감지 대상 | 시나리오 A: 상영시간표가 그 상영관에 처음 뜨는 순간 |
| 실행 위치 | 사용자의 Windows PC (창을 열어두고 상시 실행) |
| 입력 방식 | PyQt6 GUI (감시 목록을 여러 개 추가/삭제) |
| 알림 방식 | Gmail SMTP + 앱 비밀번호, 수신 주소는 설정에서 지정 |
| 데이터 수집 | 하이브리드: `requests`+`BeautifulSoup` 기본, 실패 시 Playwright 폴백 |
| 폴링 간격 | 기본 5분 (설정 가능) |
| 앱 비밀번호 저장 | `keyring` (Windows 자격 증명 관리자) |

## 3. 전체 구조

Python + PyQt6 단일 데스크톱 애플리케이션. 메인 스레드는 GUI, 백그라운드 스레드가 주기적으로 CGV를 확인한다.

```
┌─────────────────────────────────────────┐
│  PyQt6 GUI (메인 스레드)                   │
│  - 감시 목록 테이블 / 추가·삭제 / 설정      │
├─────────────────────────────────────────┤
│  Watcher (백그라운드 QThread + QTimer)     │
│  - N분마다 각 감시조건 확인 → 상태 갱신     │
├──────────────┬──────────────┬───────────┤
│ CGV Client   │  Notifier    │  Store     │
│ (조회·파싱)   │ (Gmail SMTP) │ (설정저장) │
└──────────────┴──────────────┴───────────┘
```

## 4. 핵심 감지 로직 (시나리오 A)

CGV의 상영시간표 endpoint는 **상영관 코드 + 날짜**를 주면 그 날 그 관의 **모든 영화 상영표**를 반환한다. 따라서:

- 감시조건 = `(상영관, 날짜, 영화 제목)`
- 매 주기마다 `상영관 + 날짜` 조회 → 반환된 데이터 안에 **대상 영화 제목이 등장하는지**(부분일치) 확인
- **이전 확인 때 없었는데(0개) 이번에 생김(1개 이상)** = 예매 오픈 → 메일 발송
- 발송 후 해당 조건은 `완료(opened)` 상태로 전이하여 중복 메일 방지
- GUI 상태 표시: `대기중` / `열림🔔` / `오류`

장점: 영화 코드를 미리 알 필요 없음(제목 부분일치), 조회 1회로 다수 조건 커버 가능.

## 5. 컴포넌트 상세

### 5.1 CGV Client (`cgv/`)
- `theaters.py` — 지역/상영관 목록·코드 로드 (추가 다이얼로그 드롭다운 구성)
- `showtimes.py` — `(상영관 코드, 날짜)` → 상영 중인 영화 제목 목록 반환
  - 1차: `requests` + `BeautifulSoup`, 정상 User-Agent, 요청 간 지연/지터
  - 폴백: 1차 실패(차단/구조변경) 시 Playwright 헤드리스 렌더링 후 파싱
- 반환 형태: `list[str]`(영화 제목) 또는 구조화된 상영표. 감지에는 제목 집합이면 충분.

### 5.2 Watcher (`core/`)
- `models.py` — `Watch` 데이터클래스: `id, movie_title, theater_code, theater_name, date, status, last_checked, last_titles`
- `watcher.py` — QThread에서 QTimer로 N분마다 전체 감시 목록 순회
  - 각 Watch: showtimes 조회 → 대상 제목 등장 여부 판정 → 전이 감지 시 Notifier 호출
  - 시그널로 GUI 상태 갱신(스레드 안전)
- `store.py` — 감시 목록/설정/상태를 로컬 JSON에 저장·로드

### 5.3 Notifier (`notify/`)
- `mailer.py` — Gmail SMTP(SSL 465) + 앱 비밀번호로 발송
  - 제목 예: `[CGV] "영화제목" OO관 07/25 예매 열렸습니다`
  - 본문: 상영관/날짜/확인시각 + CGV 예매 바로가기 링크
  - 앱 비밀번호는 `keyring`에서 조회(평문 저장 안 함)

### 5.4 GUI (`gui/`)
- `main_window.py` — 감시 목록 테이블(영화 | 상영관 | 날짜 | 상태 | 마지막확인), [추가][삭제][지금 확인] 버튼
- `add_dialog.py` — 지역 드롭다운 → 상영관 드롭다운, 날짜 선택(QDateEdit), 영화 제목 입력
- `settings_dialog.py` — Gmail 주소/앱 비밀번호, 수신 주소, 폴링 간격

## 6. 데이터 흐름

1. 사용자가 추가 다이얼로그에서 조건 입력 → `Store`에 저장, 테이블에 표시
2. Watcher가 N분마다 각 조건에 대해 `showtimes` 조회
3. `last_titles`(이전 결과)와 비교하여 대상 영화가 **새로 등장**하면
4. `Notifier`가 메일 발송 → Watch 상태 `열림`으로 전이, `Store` 갱신
5. GUI 상태 컬럼 실시간 갱신

## 7. 저장 위치 및 보안

- 설정/목록/상태: `%USERPROFILE%\.cgv-watcher\config.json`
- Gmail 앱 비밀번호: `keyring`(Windows 자격 증명 관리자)에 저장, config.json에는 저장하지 않음

## 8. 에러 처리

- 네트워크/파싱 오류: 크래시 없이 로그 기록 후 다음 주기 재시도, GUI 상태 `오류` 표시
- 1차 조회 실패 시 자동으로 Playwright 폴백
- SMTP 실패: 상태에 오류 표시 + 로그, 다음 주기 재시도
- 과도한 요청 방지: 기본 5분 간격 + 지터, 정상 헤더 사용

## 9. 테스트 전략

- `showtimes` 파서: 저장한 실제 응답 HTML 픽스처로 단위 테스트
- 감지 전이 로직(0→1, 1→1 중복없음): 상태 mock 테스트
- `mailer`: SMTP mock으로 발송 포맷/호출 검증

## 10. 기술 스택

Python 3.11+, PyQt6, requests, beautifulsoup4, playwright(폴백), keyring, pytest

## 11. 범위 밖 (YAGNI)

- 자동 좌석 선점/결제
- 취소표(재오픈) 감지 (시나리오 B)
- 클라우드 배포, 다중 사용자
- 카카오톡/텔레그램/윈도우 팝업 알림 (추후 확장 여지)
